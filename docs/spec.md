既存の Google スプレッドシート「資産シミュレーション」（以下「現行スプシ」）の計算ロジックを読み解き、Web アプリの仕様に落とし込んだもの。

- 1章: 現行スプシが何をどう計算しているか（現状分析）

- 末尾: 要確認事項

> 公開リポジトリのため、個人名・実際の金額は記載しない。人物は「本人」「配偶者」「子1」「子2」と表記し、金額は計算の構造を説明するための例として必要最小限にとどめる。

## 1. 現行スプシの構造

### 1.1 シート構成

| シート | 内容 |
| --- | --- |
| 月別_１馬力１子 | 月単位のキャッシュフロー表（約60年＝720行）。メインの計算 |
| 月別_１馬力２子 | 同上、子2人のシナリオ |
| 月別_２馬力１子 | 同上、配偶者が働き続けるシナリオ |
| 年間計_１馬力１子 | 月別シートを年単位に集計（フロー＝年合計、残高＝12月末時点） |
| パラメータ | インフレ率・想定利回りの共通値 |
| （別ファイル）住宅購入について › 住宅ローン試算 | 変動／固定35年ローンの返済表。月別シートの「家賃」列に IMPORTRANGE で取り込み |

シナリオ違いを**シートごとコピー**して作っている。シナリオ間の差分は手入力の値と一部の式。

### 1.2 パラメータ

| 項目 | 値（年率） | 使われ方 |
| --- | --- | --- |
| 年間インフレ率 | 1.25% | 生活費・小遣い・一部収入を**毎年1月**に一括で掛ける |
| 全世界株式 想定利回り | 5% | NISA（本人・配偶者） |
| NASDAQ100 想定利回り | 7% | iDeCo（本人） |
| 自社株 想定利回り | 1% | 持株会 |
| （式に直書き）401k | 2% | 配偶者の企業型DC |
| （式に直書き）個人年金保険 | 0.3% | 配偶者の個人年金 |

月次の運用は `残高 × 利回り^(1/12) + 当月拠出`（複利を月割り）。401k と個人年金だけは `残高 × (1 + 年率/12)`（単利の月割り）で、方式が揃っていない。

### 1.3 月別シートの列（1行＝1か月）

| 区分 | 列 | 計算 |
| --- | --- | --- |
| 時間 | 年 / 計算用月(YYYYMM) / 年月 | 年月は前行 + 1か月 |
| 年齢 | 親 / 子（子1・子2） | 誕生月に +1 |
| 収入 | 本人手取 / 配偶者手取 / その他収入 | **手取り額を直接入力**。値が変わる月だけ手で書き換える |
| | 収入合計 | 3列の合計 |
| 支出 | 家賃（住居費） / 光熱通信 / 保険 / サブスク / 食費日用品 / 交通費 / 医療費 / 養育教育費 / 美容服飾費 / 交際費 / 特別費 / 本人小遣い / 配偶者小遣い | 前月と同額。毎年1月にインフレ率を掛ける（「インフレ考慮」列）。保険・家賃はインフレ対象外 |
| | 支出合計 / 収入−支出 | |
| 拠出（月の投資額） | 本人NISA / 配偶者NISA / 本人自社株 / 本人iDeCo / 配偶者401k / 配偶者個人年金 | 手入力。取り崩し期はマイナス値（＝引き出し） |
| 残高 | 普通預金 | `前月残高 + (収入−支出) − 拠出合計 + 前月401k拠出/2 + 当月自社株拠出/6` |
| | 各口座残高 | `前月残高 × 月利 + 当月拠出` |
| | 流動資産総額 | 普通預金 + NISA×2 + 自社株 |
| | 資産総額 | 上記 + iDeCo + 401k + 個人年金 |
| メモ | イベント | 自由記述（子の誕生、育休、復職、住宅購入など） |

### 1.4 時系列で織り込まれている前提（1馬力1子の例）

| 時期 | 内容 | スプシ上の表現 |
| --- | --- | --- |
| 開始直後 | 引っ越し、一時金の受け取り | その他収入・特別費に一時金 |

| 住宅購入 | 頭金500万、ローン6,000万・35年 | 頭金は購入前月の家賃に加算。以降はローン試算シートの月額を取り込み |

| 配偶者退職（1馬力） | 配偶者手取り0 | 子が小学生の間はパート（時給×時間×日数の式） |
| 個人年金の払込 | 毎年4〜5月に追加拠出 | 一定期間 +35万 |
| 本人60歳 | 資産取り崩し開始、ローン一括返済 | 下記 1.6 |
| 本人65歳 | 年金生活 | 手取りを年金相当額に置き換え（と推定） |
| 本人80歳 | 施設入居 | 住居費30万/月、食費・小遣いなどを削減 |
| 本人100歳 | 計算終了 | |

### 1.5 住宅ローン試算（別ファイル）

- 借入6,000万、35年、元利均等。
- **変動金利**: 1〜5年目 2.0%、6〜10年目 2.5%、11〜15年目 3.0%、16年目以降 3.5%。5年ごとに残高と残り期間で `PMT` を再計算して月額を見直す（5年ルール・125%ルールは考慮していない）。
- **固定金利**: 4.0% のシナリオも並べて試算（月別シートでは変動を採用）。
- 繰上返済額の列があり、月額に加算できる。
- 月別シートは「月額(総額)」を家賃列に取り込み、本人60歳の1月に**ローン残高を一括返済**として家賃列に計上している。

### 1.6 60歳以降の取り崩しロジック（現行スプシの中で最も複雑な部分）

本人60歳の1月に以下を一度に行う。

1. **NISA（本人）**: 2,500万を一括で取り崩し（住宅ローン一括返済の原資）。翌月以降は残高の年4%を月割りで取り崩し。
2. **NISA（配偶者）**: 全額取り崩し。
3. **自社株**: 全額売却。
4. **iDeCo**: 退職所得としての税額を計算して残高から差し引き
   `((残高 − 800万 − 70万×18年) / 2 × 23% − 63.6万) × 1.021`
   （退職所得控除・1/2課税・所得税の速算表・復興特別所得税を手で当てはめている）。
5. **401k・個人年金**: 毎月少額ずつ取り崩し（年1.5〜4%）。

翌月以降は **普通預金を500万に保つように iDeCo から補填**する。
`普通預金(前月) + 収支 − 他口座の取り崩し < 500万` なら、不足分を iDeCo から引き出す。iDeCo からの引き出し額は1.2倍して残高から差し引く（税・手数料を見込んだものと推定）。

### 1.7 シナリオ間の差分

| 項目 | 1馬力1子 | 2馬力1子 | 1馬力2子 |
| --- | --- | --- | --- |
| 配偶者の働き方 | 退職し、子の小学校入学後にパート | 時短（フルの75%）→ 時短終了後にフルへ戻す | 退職し、パート |
| 児童手当 | 1人分 | 1人分 | 2人分（+3万/月） |
| 食費 | 子の成長で +2万 | 同左 | 子ごとに +2万 |
| 教育費 | 1人分を段階的に | 同左 | 2人分を段階的に。大学期は特に厚い |
| 子の独立後 | 食費×0.75 | 同左 | 食費×0.8 を2回 |

## 2. 現行スプシの論点（Web 化で直したい点）

### 2.1 入力・運用面

- **値を月ごとに手で書き換える**ため、条件を1つ変えると多くのセルを直すことになる。シナリオごとにシートを複製しているので、修正漏れも起きやすい。
- 収入が手取りの直接入力なので、昇給・時短・育休・退職・年金などを毎回自分で計算する必要がある。
- イベント欄はメモにすぎず、計算とつながっていない。

### 2.2 計算の正確さ

| # | 論点 | 現行 | あるべき姿（案） |
| --- | --- | --- | --- |
| 1 | 運用利回りの月割り | 口座によって複利と単利が混在 | 複利の月割り `(1+r)^(1/12)−1` に統一 |
| 2 | インフレ | 1月に一括で掛ける。家賃・保険は対象外。収入は一部の期間だけインフレ | 費目ごとに「インフレ連動する／しない」を設定。収入は昇給率を別パラメータにする |
| 3 | NISA の非課税枠 | 上限チェックなし | 生涯1,800万（うち成長投資枠1,200万）、年360万を検証。超過分は課税口座へ |
| 4 | 売却時の課税 | 自社株の売却益は非課税扱い | 課税口座・自社株は譲渡益に20.315%を課税（取得価額を管理） |
| 5 | iDeCo の受け取り | 一時金として課税したうえで残高は運用を続け、さらに引き出し時に1.2倍している（**二重に課税**） | **一時金で全額受け取り**、退職所得として一度だけ課税する（4.7）。年金受取・併用は v1 |
| 6 | 退職所得控除 | iDeCo だけで使っている。勤続年数は固定値 | 会社の退職金と iDeCo の受け取りタイミングから、控除の重複調整（5年／19年ルール）を考える |
| 7 | 公的年金 | 65歳以降の手取りとして手入力（と推定） | 加入履歴（厚生年金の期間・平均年収）から概算。繰上げ・繰下げも選べるように |
| 8 | 住宅ローン | 5年ごとに PMT を再計算 | 変動金利の5年ルール・125%ルールあり／なしを選択。繰上返済（期間短縮／返済額軽減）に対応 |
| 9 | 住宅ローン控除・年末調整の還付 | 年末に概算の固定額（+35万、+8万）を加算 | 年末のローン残高、iDeCo・DC の掛金、生命保険料などの控除額から税額を計算し、還付・減税額を求める |
| 10 | 住宅の維持費 | 計上なし（と思われる） | 固定資産税・修繕積立金・管理費・火災保険・リフォーム（周期的）を計上 |
| 11 | 普通預金の補正項 | `+ 401k拠出/2 + 自社株拠出/6` で、会社のマッチング拠出と持株会の奨励金を預金側に戻している | 口座に「会社負担分（マッチング・奨励金）」を明示的に持たせ、本人負担分だけを家計から差し引く（**MVP の後**） |
| 12 | 取り崩しの順序 | 口座ごとに率や金額を直書き | 「生活防衛資金を○万円保つ」「取り崩しの優先順（預金→課税口座→NISA→DC）」「定率／定額」をルールとして設定 |
| 13 | 資金ショート | 普通預金がマイナスでも計算は続く | 預金が下限を割ったら警告。ルールに従って自動で取り崩し、それでも足りない月を「破綻月」として表示 |

## 3. Web アプリの方針

### 3.1 ゴール

- **GitHub Pages で一般公開**し、誰でもブラウザだけで使える。
- スプシに慣れていない人でも、**10分程度の入力で生涯のキャッシュフローの全体像**が見える。
- 慣れた人は詳細設定を開けば、現行スプシより正確に試算できる。**計算の正しさを、現行スプシの数値の再現より優先する。**
- シナリオ（共働き／片働き、子の人数、住宅の購入／賃貸など）を並べて比べられる。

### 3.1.1 想定利用者

- 開発者本人とその家族・知人。URL は公開されるが、広く宣伝はしない。
- そのため、MVP は**会社員（厚生年金・健康保険組合／協会けんぽ）の世帯**に絞る。自営業・フリーランス（国民年金・国保・青色申告）や公務員（共済）に特有の計算は扱わない。
- 配偶者がパート・専業主婦（夫）の場合の扶養（第3号被保険者、配偶者控除）は MVP で扱う。

### 3.1.2 一般公開に伴う前提

- **家計データはサーバーに送らない。** 静的サイトとして配信し、計算と保存はすべて利用者のブラウザの中で行う。
- 共有は JSON ファイルの書き出し／読み込みで行う。URL で共有する場合は、データを URL のフラグメント（`#` 以降。サーバーに送信されない）に入れる（v2）。
- リポジトリには実在の家計データを置かない。サンプルデータは架空の世帯で作る。
- 画面に「試算であり、金融・税務の助言ではない」旨の注記と、計算に使っている制度の年版を表示する。

### 3.2 入力を減らすための設計原則

1. **イベント駆動**: 月ごとの値を入力させない。「いつ・何が起きるか（ライフイベント）」を入力すると、それが月次の値に展開される。
2. **賢い既定値**: 教育費・児童手当・税・社会保険・年金などは、公的な統計や制度から既定値を自動で入れる。ユーザーは必要なときだけ上書きする。
3. **段階的な詳細化**: 「かんたん入力」（必須項目だけ）→「詳細設定」（費目別・口座別）の2段階にする。
4. **シナリオは差分で持つ**: ベースのシナリオを複製し、変えた項目だけを保存する。比較画面では差分をハイライトする。

### 3.3 対象範囲（MVP とその後）

| フェーズ | 範囲 |
| --- | --- |
| **MVP** | 月次エンジン、ライフイベント、口座、取り崩しルール、シナリオ比較、グラフ、ブラウザ内保存、GitHub Pages への公開。**税と制度の計算は MVP に含める**: 額面年収→手取り、年末調整（iDeCo・DC 掛金、生命保険料などの控除）、住宅ローン控除、iDeCo の一時金受取（退職所得）、NISA 枠、課税口座・持株の譲渡益課税、児童手当、育休給付 |
| v0.4（実装済み） | 公的年金の自動概算、加給年金、在職老齢年金、遺族年金と必要保障額、産休・出産手当金、育児時短就業給付、パート・扶養、退職金との控除の重複調整、変動金利の5年／125%ルール、団信、多子世帯の大学無償化・保育料の多子軽減、子ども・子育て支援金、65歳以上の介護保険料、モンテカルロ、いまの物価での表示、年ごとの内訳、CSV の全項目書き出し |
| v1 | 会社のマッチング拠出・持株会の奨励金、iDeCo の年金受取・併用、親の介護費用、2028年からの遺族厚生年金の見直し |
| v2 | URL での共有、スプシへの書き出し、自営業・公務員への対応 |

## 4. ドメインモデル

```
Plan（ライフプラン）
├─ settings: 開始年月, 終了条件(本人◯歳まで), インフレ率, 昇給率
├─ household
│   ├─ members[]: 本人 / 配偶者 / 子（生年月, 役割）
├─ incomes[]      : 収入ソース（給与・年金・手当・一時金…）
├─ expenses[]     : 支出カテゴリ（基本生活費・教育・住居・保険…）
├─ housing        : 住居プラン（賃貸 / 購入 + ローン）
├─ accounts[]     : 資産口座（預金・NISA・iDeCo・DC・課税口座・持株・保険）
├─ events[]       : ライフイベント（時点 + 効果）
├─ withdrawalRule : 取り崩しルール
└─ scenarios[]    : 上記に対する差分（パッチ）
```

### 4.1 Member（世帯構成）

| 項目 | 型 | 備考 |
| --- | --- | --- |
| id, role | `self` / `spouse` / `child` | |
| birthYearMonth | YYYY-MM | 子は「予定」も可 |
| 子のみ: educationPath | 幼稚園〜大学の公立／私立、自宅／下宿 | 教育費の既定値を決める |

### 4.2 Income（収入）

| 種類 | 入力 | 計算 |
| --- | --- | --- |
| 給与 | 額面年収（月給・賞与）、昇給率、定年年齢、再雇用後の年収 | 額面→手取り（所得税・住民税・社会保険）を自動計算。年末調整の還付も控除額から計算する（4.7） |
| 育休 | 期間 | 給付金（最初の180日は67%、以降50%。手取り10割相当の新制度にも対応）を自動計算 |
| 時短 | 期間、割合 | 給与 × 割合 |
| パート | 時給 × 時間 × 日数 | 扶養の壁（106万・130万など）を警告 |
| 公的年金 | 人ごとに受給開始年齢と見込み額（ねんきん定期便の65歳時点の年額）を入力 | 繰上げ（1か月あたり−0.4%）・繰下げ（+0.7%）を適用。年金からは介護保険料・国保・税を差し引いて手取りにする。加入履歴からの自動概算は v1。現行スプシでは65歳以降の手取り（月15万＋10万）として入っていた |
| 退職金 | 金額、受取時期 | 退職所得控除を適用 |
| 児童手当 | 自動 | 子の年齢・人数から制度どおりに計算 |
| 住宅ローン控除 | 自動 | 4.7 を参照 |
| その他（一時金・定期収入） | 金額、時期、繰り返し | 祝い金・ふるさと納税の還付など |

### 4.3 Expense（支出）

現行スプシの費目を引き継ぎ、各費目に「インフレ連動」フラグを持たせる。

| カテゴリ | 既定のインフレ連動 | かんたん入力での扱い |
| --- | --- | --- |
| 基本生活費（光熱通信・食費日用品・交通費・医療費・美容服飾・交際） | する | 「月の生活費」1項目にまとめ、詳細で費目に分割 |
| サブスク | する | 生活費に含める |
| 保険 | しない | 月額 |
| 小遣い（人別） | する | 月額 |
| 特別費（旅行・家電・車など） | する | 年額（支出月を指定） |
| 教育費 | する | 子の進路から自動。上書き可 |
| 子の生活費の増分 | する | 子の年齢に応じて自動で加算（現行の「食費 +2万」に相当） |
| 住居費 | 賃貸の家賃はしない（更新時の値上げ率は設定可） | 4.5 を参照 |
| 老後の変化 | ー | 「退職後の生活費は ◯%」「施設入居（年齢・月額）」をイベントで |

### 4.4 Account（資産口座）

| 種類 | 主なパラメータ | 税 | 制約 |
| --- | --- | --- | --- |
| 普通預金 | 初期残高、金利 | 利子に20.315% | 「生活防衛資金の下限」 |
| NISA | 初期残高（**時価と取得額を利用者が入力**。取得額が未入力なら時価＝取得額とみなす）、月の積立額、想定利回り | 非課税 | 年360万（つみたて120万＋成長240万）、生涯1,800万（成長1,200万）。売却した分の枠は翌年に復活 |
| 課税口座（特定口座） | 同上 | 譲渡益に20.315% | |
| iDeCo | 初期残高、掛金、想定利回り、受取開始年齢 | 掛金は全額所得控除。受取は**一時金**で、退職所得として課税（年金受取・併用は v1） | 掛金の上限は職業で決まる。拠出は65歳未満まで |
| 企業型DC（401k） | 同上（会社掛金・マッチング拠出は v1） | 同上 | |
| 持株会 | 拠出額、想定利回り（奨励金は v1） | 売却時に譲渡益課税 | |
| 個人年金保険 | 払込額・払込期間、受取開始・期間、予定利率 | 雑所得（v1） | |

運用は月次の複利 `残高 × (1+r)^(1/12) + 拠出 − 取り崩し` で揃える。各口座は**取得額（元本）**も持ち、売却時の課税計算に使う。

### 4.5 Housing（住居）

- **賃貸**: 家賃、更新料（2年ごと）、引っ越し費用（イベントとして）。
- **購入**: 物件価格、頭金、諸費用（物件価格の◯%）、購入年月、住宅の性能区分（ローン控除の上限に使う）。
- **ローン**: 借入額、期間、元利均等／元金均等、金利タイプ。
  - 固定: 金利1つ。
  - 変動: 金利の推移を「◯年目から◯%」の表で入力（既定は現行スプシの 2.0→2.5→3.0→3.5%）。5年ルール・125%ルールあり／なしを選べる。
  - 繰上返済: 時期、額、期間短縮型／返済額軽減型。「◯歳で残債を一括返済」も選べる（現行スプシの60歳一括返済）。
- **維持費**: 現行スプシでは特別費に含めていたが、アプリでは住居の**独立した費目**にする。
  - 管理費・修繕積立金（マンション）: 月額。修繕積立金は◯年ごとに◯%上げる段階増額を設定可。
  - 火災保険・地震保険: 年額（地震保険料は年末調整の控除に使う）。
  - 修繕・リフォーム（戸建）: 「◯年ごとに◯万円」（例: 外壁・屋根15年ごと、水回り20年ごと）。
  - 固定資産税・都市計画税: **物件価格から自動で概算**し、上書きもできる（下記）。

#### 固定資産税・都市計画税の自動概算

入力: 物件価格、土地と建物の内訳（未入力なら戸建は土地5:建物5、マンションは土地2:建物8を既定値にする）、戸建／マンション、新築／中古、長期優良住宅か、土地の面積（200㎡以下か）、構造（木造／非木造）。

| 項目 | 計算 |
| --- | --- |
| 土地の評価額 | 土地価格 × 70%（固定資産税評価額は公示価格のおよそ7割） |
| 建物の評価額 | 建物価格 × 60%（再建築価格の目安）。経年で減価し、木造は約25年、非木造は約45年で下限（当初の20%）に達するように毎年下げる |
| 住宅用地の特例 | 200㎡以下の部分は、固定資産税の課税標準を1/6、都市計画税を1/3にする |
| 新築住宅の減額 | 建物の固定資産税を1/2にする。戸建は3年間、マンションは5年間。長期優良住宅はそれぞれ5年・7年 |
| 税率 | 固定資産税1.4%、都市計画税0.3%（上限）。自治体によって違うので設定で変えられる |
| 評価替え | 3年ごと。建物の減価は評価替えの年にまとめて反映する |
| 支払い | 年税額を4回（4・7・12・2月）に分けて支出する。簡易表示では月割りにもできる |

概算であることを画面に明記し、納税通知書の金額がある場合は上書きしてもらう。
- 返済表（月ごとの元本・利息・残高）は詳細画面で見られるようにする。

### 4.6 Event（ライフイベント）

イベントは「時点」と「効果」の組み合わせ。時点は年月の指定に加え、**年齢などの相対指定**もできる（例: 子が6歳の4月）。

| イベント | 効果（自動で展開されるもの） |
| --- | --- |
| 出産 | 子の Member を追加、出産費用（一時金と相殺）、児童手当開始、育休の起点 |
| 育休・時短・復職・退職・転職 | 該当メンバーの給与を変更 |
| 入園・入学 | 子の進路に応じて教育費を切り替え |
| 子の独立 | 子の生活費の増分と教育費を終了 |
| 住宅購入・住み替え | Housing の切り替え、頭金・諸費用の支出 |
| 車の購入・買い替え | 一時支出（周期的な繰り返しも可） |
| 定年・再雇用・年金開始 | 給与→再雇用給与→公的年金へ |
| 施設入居 | 住居費・生活費の変更 |
| 一時金（受け取り・支出） | 指定月の収入・支出 |
| 自由入力 | 任意の費目を「◯月から◯円に変更」「◯月だけ◯円」 |

### 4.7 税・社会保険（MVP）

現行スプシでは「年末調整の還付 +8万」「住宅ローン控除 +35万」を概算の固定額で入れていたが、アプリでは控除額から計算する。

- 額面→手取り: 社会保険料（健保・厚生年金・雇用保険の料率は設定可）、給与所得控除、基礎控除、配偶者控除、扶養控除、所得税（復興特別所得税を含む）、住民税（前年所得ベースで1年ずらす）。
- **年末調整の還付**: 毎月の源泉徴収は給与と扶養の情報だけで計算し、12月に以下の控除を反映した年税額との差を還付として収入に計上する。
  - 小規模企業共済等掛金控除: iDeCo・企業型DC のマッチング拠出の掛金（全額）
  - 生命保険料控除: 一般・介護医療・個人年金の3区分（新制度でそれぞれ最大4万、合計12万）。保険の支出に区分を持たせる
  - 地震保険料控除: 最大5万
- **住宅ローン控除**: 年末のローン残高 × 0.7%。上限は入居年と性能区分で決まる。所得税から引ききれない分は住民税から（上限あり）。控除期間は13年（中古は10年）。所得税分は12月（初年度は確定申告の翌年3月）、住民税分は翌年6月からの住民税の減額として反映する。
- **退職所得**（iDeCo の一時金、退職金）: `(受取額 − 退職所得控除) × 1/2` に所得税（復興特別所得税を含む）と住民税10%。退職所得控除は、年数20年までは40万×年数（最低80万）、それ以降は800万＋70万×(年数−20)。iDeCo では加入年数を年数として使う。
- **一時金受取の処理**: 受取年齢の月に iDeCo の残高を全額取り崩し、税引き後の額を預金に入れる（または指定した口座に移す）。受け取った後に iDeCo 残高は残らない。現行スプシの「課税後も運用を続け、引き出し時にさらに1.2倍」の扱いはやめる。
- 譲渡益課税: 課税口座・持株の売却益に20.315%。売却額のうち「元本の割合」は非課税として計算する。
- 公的年金等控除・年金への課税。
- 計算に使う税制は**年版のテーブル**として持ち、制度改正に追従できるようにする。

### 4.8 取り崩しルール

現行スプシの「普通預金を500万に保つように iDeCo から補填」を一般化する。

- **生活防衛資金**: 普通預金の下限額（既定は生活費の6か月分）。
- **不足時の補填順**: 例: 課税口座 → NISA → 個人年金。順序はドラッグで入れ替えられる。iDeCo・DC は一時金で受け取るので補填の対象にしない（受け取った後は預金や指定口座の一部として扱う）。
- **計画的な取り崩し**: 口座ごとに「◯歳から、定率◯%／定額◯万円」。
- **余剰時の積立**: 預金が上限を超えたら、超過分を指定口座へ積み立てる（任意）。
- 売却時は口座の課税ルールに従って税を差し引き、手取り額で補填する。

## 5. 計算エンジン

### 5.1 時間軸

- 単位は**月**。開始年月から「本人が◯歳になる年の12月」まで（既定は100歳）。
- 年次の値は月次を集計して出す。フローは年合計、残高は12月末時点（現行の年間計シートと同じ）。

### 5.2 1か月の計算順序

```
for each month t:
  1. イベントを適用（その月に有効になる設定の切り替え）
  2. インフレ・昇給を適用（年1回の月を設定可。既定は1月）
  3. 収入を計算（給与・年金・手当・一時金・控除による還付）
  4. 支出を計算（生活費・教育・住居（ローン返済表）・保険・特別費）
  5. 口座への拠出（積立額。NISA 枠をチェックし、超えた分は課税口座へ）
  6. 運用益を反映（各口座: 残高 × 月利）
  7. 計画的な取り崩し（ルールどおり、税引き後の額を預金へ）
  8. 預金残高 = 前月 + 収入 − 支出 − 拠出 + 取り崩し
  9. 下限チェック: 下限を割ったら補填ルールで取り崩す。それでも足りなければ不足フラグを立てる
 10. その月のスナップショットを記録
```

- 純粋関数 `simulate(plan) → MonthlyRow[]` として実装し、UI から切り離す（テストしやすく、Web Worker でも動かせる）。
- 金額は円の整数で丸めるタイミングを決めておく（内部は小数で持ち、表示で丸める）。

### 5.3 出力（MonthlyRow）

年月、各メンバーの年齢、収入の内訳、支出の内訳、口座ごとの拠出・運用益・取り崩し・残高・元本、預金残高、流動資産総額（年金系を除く）、資産総額、ローン残高、税額、その月のイベント、警告。

### 5.4 検証

- **正しさの検証が最優先**: 制度計算（手取り、年末調整、ローン控除、退職所得、NISA 枠、譲渡益課税、児童手当、育休給付）は単体テストで、国税庁・自治体・金融庁などの公的な計算例と照合する。
- **現行スプシとの突き合わせ（参考）**: 現行スプシと同じ前提のプランを作り、主要な時点の資産総額の差を一覧にする。一致させることは目標にせず、差が出た理由が 2章の論点で説明できることを確認する。
- 口座の残高推移は、運用利回り0%・インフレ0% で手計算と一致することを確認する（エンジンの足し引きの検証）。

## 7. 技術構成（案）

- フロントエンドのみの SPA（TypeScript + React + Vite）。**GitHub Pages に GitHub Actions でデプロイ**する。計算はすべてブラウザで行い、サーバーに家計データを送らない。
- 保存はブラウザ（localStorage）と JSON の書き出し／読み込み。アカウントやサーバー側の保存は持たない。
- グラフ: Recharts などの軽量ライブラリ。
- 計算エンジンは `packages/engine` のように独立させ、Vitest でテストする。
- 制度パラメータ（税率表、児童手当、教育費の統計値、NISA 枠など）は年版付きの JSON で管理する。

## 9. v0.4 の見直し（公開版の操作レビューから）

### 9.1 見つかった問題と対応

| 観点 | 問題 | 対応 |
| --- | --- | --- |
| 入力 | 「出産後に退職し、子が大きくなったらパートで再就職」（スプシの1馬力シナリオ）を表現できない | かんたん入力に「いまの働き方（会社員／パート／働いていない）」「出産する」「出産・育休のあと（復職／退職→パート再就職）」を追加 |
| 入力 | 公的年金の見込み額を自分で調べる必要がある | 給与の履歴から自動で概算（既定）。ねんきん定期便の手入力も選べる。かんたん入力の最後に見込み額を表示 |
| 計算 | 退職金と iDeCo 一時金の退職所得控除を別々に満額使っていた | 受取間隔（19年／9年／4年）と加入期間の重なりで控除を調整。同じ年は合算 |
| 計算 | 老後に「毎年4%取り崩し」が既定で、使わない現金が積み上がっていた | 既定を「預金が足りなくなったときだけ売る」に変更。預金の上限を超えた分を NISA に回す設定を追加 |
| 表示 | サンプル世帯で「購入後も家賃がかかる」と誤って警告していた | 購入月の重なりは警告しないよう修正 |
| 分析 | 将来の額面しか見られず、何十年後の金額の大きさがわかりにくい | 「いまの物価で表示」切り替えを全画面に追加 |
| 分析 | 年ごとの内訳を掘り下げられない | グラフや表の年をクリックすると、収入・税・支出の内訳、口座の動き、月ごとの動きを表示 |
| 分析 | 利回りが一定の前提しかない | モンテカルロ（300通り）で、お金が尽きない確率と資産の分布を表示 |
| 分析 | 万一のときの備えが検討できない | 「万一の備え」画面: 遺族年金・団信・死亡保険金・死亡退職金を反映した資金推移と必要保障額（亡くなる年齢ごと） |

### 9.2 追加した制度

- 公的年金: 老齢基礎年金（満額×加入月数/480）、報酬比例部分（標準報酬×5.481/1000、上限65万円・賞与150万円）、加給年金（配偶者・子）、在職老齢年金（2026年4月から62万円）
- 遺族年金: 遺族基礎年金（子の加算）、遺族厚生年金（3/4、300月みなし、65歳からの併給調整）、中高齢寡婦加算、夫が遺される場合の年齢要件
- 出産・育児: 出産手当金（2/3・約3か月）、育児時短就業給付（10%・2歳未満）、社会保険料免除中も年金の加入期間に算入
- 社会保険: パートの扶養判定（130万円・60歳以上180万円）、国民健康保険の年齢別概算と7割軽減、65歳以上の介護保険料、子ども・子育て支援金（2026年4月〜）
- 教育: 保育料の多子軽減（2人目半額・3人目以降無料）、多子世帯の大学授業料・入学金の無償化（2025年度〜）
- 住まい: 変動金利の5年ルール・125%ルール（未払利息の精算）、団信、死亡時に購入前なら購入を取りやめて賃貸継続
